# Discord リマインダーBot 設計書

- 作成日: 2026-10-11
- 実行環境: UGREEN NAS (Docker / docker compose)
- 利用者: オーナー1人(個人用)

## 1. 目的

Discordでボットにメンションし、アバウトな日本語を書くだけでリマインダーを登録できるようにする。
外部API・大型ローカルAIは使わず、ルールベースの解釈と確認UIで「崩した言い回し」に対応する。

## 2. 利用イメージ

```
@reminder 今日の15時にサンフレ試合リマインド
@reminder 今日の18時から1時間おきに3回ゲームジャムのコンパスリマインド
@reminder 明日の昼ごろ会議
@reminder 30分後に洗濯物
@reminder 毎週月曜の朝ゴミ出し
@reminder 来週金曜 夕方 飲み会の店予約
```

返信例:

```
✅ 登録しました
📅 10/11(土) 18:00 / 19:00 / 20:00(1時間おき・3回)
📝 ゲームジャムのコンパス
[取り消し]
```

## 3. 機能要件

### 3.1 登録(メンション)
- オーナーがボットにメンションしたメッセージ(サーバーのチャンネル)、またはDMを解釈対象とする。
- オーナー以外からのメンションは無視する(反応しない)。
- 解釈結果の自信度で分岐:
  - **確定**: 即登録し、確認メッセージ+[取り消し]ボタンを返す。
  - **要確認**: 候補を表示し [✅ 登録] [🕒 時刻変更] [❌ やめる] ボタンを出す。
    - 🕒 書き直すは元の文章を入れたモーダルを開き、編集後に同じパーサーで再解釈(確定なら即登録、曖昧なら再確認)。
    - ボタンは10分で期限切れ(未登録のまま破棄)。
  - **失敗**: 解釈できなかった旨と書き方の例を返す。
- 内容(本文)が空になった場合は「リマインダー」を内容とし、要確認扱いにする。

### 3.2 通知
- 登録したチャンネル(DM登録ならDM)に `<@オーナー> ⏰ 内容` を投稿する。
- 繰り返しの場合は `(2/3回目)` のように回数を付記する(回数制限があるとき)。
- ボット停止中に過ぎた通知は、起動後に `(遅れて通知: 予定 18:00)` を付けて1回だけ送る。
  繰り返しで複数回分過ぎていた場合も、まとめて1通にし、次回は現在以降の予定にする。

### 3.2.1 スヌーズ(2026-10-15 追加。同10-12 の「未反応の再通知」を置き換え)
- 通知は1回だけ。リアクションの有無にかかわらず、勝手に再通知はしない。
- すべての通知(最初の通知も、スヌーズ後の通知も)に **💤 スヌーズ** ボタンを付ける。
- ボタンを押すと、本人にだけ見えるセレクトで時間を選べる(5分/10分/15分/30分/1時間/2時間/3時間/6時間/12時間/24時間後)。
- 選ぶと、同じ内容・同じチャンネルで、選んだ時間後に1回だけ通知する新しいリマインダーが登録される。繰り返しの元リマインダーには影響しない。
- ボタンはオーナーだけが使える。Bot の再起動・更新後も古い通知のボタンが動く(常設ボタン+DBの `notified(message_id, user_id, channel_id, content)`)。

### 3.3 管理用スラッシュコマンド(オーナーのみ)
- `/list` — 有効なリマインダー一覧(ID・次回日時・繰り返し・内容)。
- `/delete id:<ID>` — 削除。
- `/alias set word:<言葉> time:<HH:MM>` — 曖昧語の時刻を上書き・追加(例: 昼ごろ=12:30)。
- `/alias list` / `/alias delete word:<言葉>`。
- メンションでも `@reminder 一覧`、`@reminder 削除 3` を受け付ける。

## 4. 日本語解釈(parser)仕様

入力: `text: str`, `now: datetime(Asia/Tokyo)`, `aliases: dict[str, time]`
出力: `ParseResult`
```
ParseResult:
  status: "ok" | "confirm" | "fail"
  first_at: datetime            # 初回通知日時
  recurrence: Recurrence | None
  content: str
  reasons: list[str]            # 要確認の理由(表示用)
Recurrence:
  kind: "interval" | "daily" | "weekdays" | "weekly" | "monthly"
  interval: timedelta | None    # kind=interval
  weekdays: set[int] | None     # kind=weekly (0=月)
  day_of_month: int | None      # kind=monthly
  count: int | None             # 総回数(初回を含む)
  until: datetime | None        # 終了日時(含む)
```

### 4.1 正規化(前処理)
- 全角英数記号→半角(NFKC)。
- 漢数字→算用数字(「三時」→「3時」、「十五分」→「15分」、「二十一時」→「21時」)。
- 「、」「。」「!」「?」等の区切りは空白扱い。
- ユーザー辞書(alias)の語を時刻に置換。

### 4.2 日付表現
| 表現 | 解釈 |
|---|---|
| 今日 / 本日 / きょう | 今日 |
| 明日 / あした / あす | +1日 |
| 明後日 / あさって | +2日 |
| 明々後日 / しあさって | +3日 |
| 今夜 / 今晩 | 今日 + 時刻未指定なら20:00 |
| N日後 / N週間後 / Nヶ月後 | 加算 |
| (今週・来週・再来週)X曜(日) | 該当週の曜日(週は月曜始まり) |
| X曜(日) 単独 | 次に来るその曜日(今日が該当曜日で時刻が未来なら今日) |
| 週末 / 今週末 | 今週土曜 |
| 来週頭 / 週明け | 来週月曜 |
| 月末 | 今月末日(過ぎていれば来月末日) |
| 月初 / 来月頭 | 来月1日 |
| M/D, M月D日 | 今年(過去なら翌年) |
| D日 単独 | 今月(過去なら来月) |
| YYYY/M/D, YYYY年M月D日 | そのまま |

### 4.3 時刻表現
| 表現 | 解釈 |
|---|---|
| H時, H:MM, H時M分, H時半 | 時刻 |
| 午前/朝 H時, 午後/夜/夕方 H時 | 12時間制補正(夜9時→21:00) |
| H時ごろ / 頃 / くらい | H時 |
| 正午 | 12:00 |
| 曖昧語(既定値・alias上書き可) | 朝=8:00, 朝イチ=9:00, 午前中=10:00, 昼/昼ごろ/お昼=12:00, 午後=14:00, 夕方=17:00, 夜=20:00, 寝る前=23:00, 深夜=0:00(翌日) |
| N分後 / N時間後 / N時間M分後 / N秒後 | now + 差分 |
| 1時間半後 | +90分 |

- 午前午後指定なしの 1〜6時 は午後(「3時」→15:00)とみなす。日付が明示されていれば確定、なければ**要確認**。
- 午前午後指定なしの 7〜11時 は午前とみなし確定(「9時に起きる」→9:00)。
- 「夜1時」「深夜2時」は翌日の 1:00 / 2:00。
- 時刻のみ指定で今日すでに過ぎている → 明日、確定。
- 日付のみ指定で時刻なし → 9:00、**要確認**。
- 日付も時刻もなし(内容だけ) → **失敗**。

### 4.4 繰り返し表現
| 表現 | 解釈 |
|---|---|
| N分おき / N分ごと / N分毎 / N時間おき / 毎時 | interval |
| 毎日 / 毎朝(8:00) / 毎晩(20:00) | daily |
| 平日 / 平日毎日 | weekdays (月〜金) |
| 毎週X曜 / 毎週X・Y曜 / X曜と Y曜 | weekly |
| 隔週X曜 | weekly + interval 2週 |
| 毎月N日 / 毎月末 | monthly |
| 〜からN回 / N回 | count |
| 〜まで (H時まで / M/Dまで) | until |
| 〜から (H時から) | 初回日時 |

- interval で開始時刻がない場合は now + interval を初回とする。
- interval で count も until もない場合: 1日分(24時間後まで)を上限とし、**要確認**(無限通知防止)。
- interval の最小は5分(それ未満は要確認で5分に丸める)。

### 4.5 内容(本文)抽出
- 日時・繰り返しとして消費した部分を除去。
- 先頭・末尾の助詞やつなぎ語を除去: `に`, `で`, `から`, `の`, `は`, `を`, `って`。
- 末尾の依頼表現を除去: `リマインド(して)?`, `教えて`, `知らせて`, `通知(して)?`, `お願い`, `よろしく`, `って言って`, `思い出させて`。
- 例: 「今日の15時にサンフレ試合リマインド」→ 内容「サンフレ試合」。

### 4.6 テストケース(最低限・`now = 2026-10-11(日) 10:00 JST`)
| 入力 | 期待 |
|---|---|
| 今日の15時にサンフレ試合リマインド | ok, 10/11 15:00, 「サンフレ試合」 |
| 今日の18時から1時間おきに3回ゲームジャムのコンパスリマインド | ok, 10/11 18:00, interval 1h, count 3, 「ゲームジャムのコンパス」 |
| 明日の昼ごろ会議 | ok, 10/12 12:00, 「会議」 |
| 30分後に洗濯物 | ok, 10:30, 「洗濯物」 |
| 毎週月曜の朝ゴミ出し | ok, 10/12 8:00, weekly{月}, 「ゴミ出し」 |
| 来週金曜 夕方 飲み会の店予約 | ok, 10/16 17:00(週は月曜始まり。10/11は日曜) |
| 3時に電話 | confirm, 15:00 |
| 明日 歯医者 | confirm, 10/12 9:00 |
| 9時に起きる | ok, 10/12 9:00(今日は過ぎた) |
| 夜9時半に風呂 | ok, 10/11 21:30 |
| 十五時に打ち合わせ | ok, 15:00 |
| １５：３０に会議 | ok, 15:30 |
| 平日8時に体温測る | ok, weekdays 8:00 |
| 毎月25日に家賃 | confirm, 10/25 9:00, monthly 25日(時刻なし) |
| 21時まで30分おきに水飲む | ok, interval 30m, 初回10:30, until 21:00 |
| 10/20 15時 締切 | ok |
| 1時間半後に休憩終わり | ok, 11:30 |
| 月末に請求書 | confirm, 10/31 9:00 |
| 会議 | fail |

## 5. アーキテクチャ

```
reminder/
  src/reminder_bot/
    parser/
      normalize.py   # 全角・漢数字・alias置換
      datetime_rules.py  # 日付・時刻
      recurrence_rules.py  # 繰り返し
      content.py     # 本文抽出
      __init__.py    # parse(text, now, aliases) -> ParseResult
    models.py        # ParseResult, Recurrence, Reminder
    recurrence.py    # next_occurrence(reminder, after)
    store.py         # SQLite
    scheduler.py     # 30秒ごとのポーリングループ
    formatting.py    # 返信メッセージ整形
    bot.py           # discord.py: メンション・ボタン・コマンド
    main.py          # 設定読み込み・起動
  tests/
  Dockerfile
  docker-compose.yml
  .env.example
  README.md          # Discord側設定とNAS導入手順
```

- parser・recurrence・formatting は Discord に依存しない純粋関数とし、pytest で単体テストする。
- 依存: Python 3.12, discord.py 2.x, tzdata。DBは標準の sqlite3。

### 5.1 データ(SQLite, `/data/reminder.db`)
```
reminders(id, user_id, channel_id, is_dm, content,
          next_at, kind, interval_sec, weekdays, day_of_month, week_step,
          count_total, count_done, until_at, created_at, active)
aliases(word PRIMARY KEY, hh, mm)
```

### 5.2 スケジューラ
- 30秒ごとに `active=1 AND next_at <= now` を取得して通知。
- 通知後、`next_occurrence` で次回を計算。count到達・until超過・次回なし → active=0。
- 通知送信失敗(チャンネル削除等)はログに出し、DMへのフォールバックを1回試みる。

## 6. 設定・導入
- `.env`: `DISCORD_TOKEN`, `OWNER_ID`, `TZ=Asia/Tokyo`。
- Discord Developer Portal: Bot作成、**Message Content Intent** 有効化、招待URL(scope: bot, applications.commands / 権限: メッセージ送信・閲覧・埋め込み)。
- NAS: プロジェクトフォルダを配置 → `docker compose up -d --build`。`./data` をボリュームとして永続化。`restart: unless-stopped`。
